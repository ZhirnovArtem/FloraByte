# План проверки устойчивости (FR-SAST-03)

Для каждой эталонной конструкции подготовить отдельную копию проекта и применить мутации по одной, затем в комбинации:

1. Переименовать пакеты, классы, методы и локальные переменные, не меняя семантику.
2. Переформатировать вызовы: переносы строк, пробелы, trailing lambda, разбиение цепочки DSL.
3. Представить Security DSL в двух стилях: `authorizeHttpRequests { ... }` и цепочкой `.and()`.
4. Для SQL/command injection заменить интерполяцию `$x` на `${x}`, конкатенацию, `String.format`, raw triple-quoted string и `trimIndent()`.
5. Вынести значения в `const val`; добавить импорт с alias.
6. Переместить конфигурационные ключи между `application.properties`, `application.yml`, `application-dev.yml`; проверить вложенный YAML.
7. Добавить контрольные ловушки: комментарии, обычные строки, тестовые файлы, безопасные параметры SQL и фиксированные команды.

Метрика считается по эталонным находкам после нормализации координат (для мутаций с переносами строк сохранять mapping исходная строка → новая строка). Recall = TP/(TP+FN), precision = TP/(TP+FP). Приёмка проекта: recall не ниже 0,90; FP не более 2 на 10 эталонных находок. Пока эталон организаторов и проект не приложены, численные значения не рассчитываются.
